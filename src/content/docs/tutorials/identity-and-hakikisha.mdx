# Identity and Hakikisha APIs

This guide covers four APIs for identity and account verification:

- **Mobile Number Validation** checks whether a Safaricom number is registered to an identity document.
- **SIM Swap** checks the date of the most recent SIM swap.
- **B2C Hakikisha** looks up a customer's masked name before a payout.
- **C2B Hakikisha** lets Safaricom look up an account name before a C2B payment.

These APIs may require Safaricom approval or onboarding, and may not be enabled for default sandbox apps. Mobile Number Validation is commercial and may be billed per request.

## Mobile Number Validation

Use this API to check whether a phone number is registered to a supplied identity document.

```php
use Starnerz\LaravelDaraja\Enums\MobileIdType;
use Starnerz\LaravelDaraja\Facades\Daraja;

$result = Daraja::mobileNumberValidation()->validate(
    phone: '0712345678',
    idType: MobileIdType::NationalId,
    idNumber: '12345678',
);

if ($result->matches()) {
    // The number matches the supplied identity document.
}
```

`phone` accepts common Kenyan phone-number formats and is normalized before sending. Supported identity types are:

| Enum | Safaricom value |
|---|---|
| `MobileIdType::NationalId` | `01` |
| `MobileIdType::MilitaryId` | `02` |
| `MobileIdType::Passport` | `05` |

The shortcode defaults to `laravel-daraja.initiator.short_code`. Pass `shortCode` to override it, or `requestRefId` to provide your own request reference.

The response exposes `responseRefId`, `responseCode`, `responseMessage`, and `status`, along with the raw response. Use `$result->matches()` to check the match result.

> **Handle identity data carefully.** Identity numbers and phone numbers are sensitive. Store them only when necessary, restrict access, and avoid including them in application logs.

## SIM Swap

Query the most recent SIM swap date for a Safaricom number:

```php
use Starnerz\LaravelDaraja\Facades\Daraja;

$result = Daraja::simSwap()->query('0712345678');

if ($result->successful()) {
    $lastSwapDate = $result->lastSwapDate;
}
```

The phone number is normalized before it is sent. The response exposes `requestRefId`, `responseCode`, `responseDescription`, and `lastSwapDate`, as well as the raw response. SIM-swap information is one signal to consider in your own risk checks; apply your own policy before approving a transaction.

## B2C Hakikisha

B2C Hakikisha looks up the masked name associated with a number. Use it to help verify a recipient before initiating a B2C payout:

```php
use Starnerz\LaravelDaraja\Facades\Daraja;

$customer = Daraja::b2cHakikisha()->validate('0712345678');

if ($customer->successful()) {
    $name = trim(implode(' ', [
        $customer->firstName,
        $customer->middleName,
        $customer->lastName,
    ]));

    // Show the masked name for confirmation before making the payout.
}
```

The request uses the configured initiator shortcode by default and includes a generated request ID and Unix timestamp. You can override them:

```php
$customer = Daraja::b2cHakikisha()->validate(
    phone: '0712345678',
    shortCode: '123456',
    requestId: (string) Str::uuid(),
    timestamp: (string) time(),
);
```

The response exposes `requestId`, `timestamp`, `status`, `message`, and the masked name fields `firstName`, `middleName`, and `lastName`. Check `successful()` before using the name. Safaricom onboarding is required; a request from an app that is not enabled may fail.

## C2B Hakikisha

C2B Hakikisha is receiver-side: Safaricom calls endpoints in your Laravel app to request an access token and resolve an account name. It is not an outbound Daraja request.

### Configure the receiver

Enable the package routes and set the partner credentials provided for your integration:

```dotenv
DARAJA_ROUTES_ENABLED=true
DARAJA_C2B_HAKIKISHA_USERNAME=partner-user
DARAJA_C2B_HAKIKISHA_PASSWORD=replace-with-a-secret
DARAJA_C2B_HAKIKISHA_TOKEN_TTL=3599
```

Keep these credentials secret and serve the endpoints over HTTPS. With the default route prefix, the routes are:

| Purpose | Method and path |
|---|---|
| Token | `POST /daraja/c2b-hakikisha/token?grant_type=client_credentials` |
| Account validation | `POST /daraja/c2b-hakikisha/validation` |

If you change `DARAJA_ROUTES_PREFIX`, use that prefix in the URLs you register with Safaricom.

### Register an account resolver

Register the resolver in an application service provider’s `boot()` method. It receives the account number and shortcode from the request and should return the matching account name, or `null` if there is no match.

```php
use Starnerz\LaravelDaraja\Facades\Daraja;

public function boot(): void
{
    Daraja::resolveC2BAccountUsing(
        fn (string $accountNumber, string $shortcode): ?string =>
            Account::query()
                ->where('shortcode', $shortcode)
                ->where('number', $accountNumber)
                ->value('name'),
    );
}
```

Make sure the lookup verifies that the account belongs to the submitted shortcode. Do not return an account name based only on an unverified account number.

### Request flow

1. Safaricom requests a token using HTTP Basic authentication with the configured username and password.
2. Your app returns an access token. It is cached for the configured TTL.
3. Safaricom sends the account number and shortcode to the validation route with that token as a Bearer token.
4. Your resolver looks up the account name and the route returns the result.

The validation request has this shape:

```json
{
  "requestId": "dcd1c2ab-7a26-4170-939d-9dc2e879b0e5",
  "timestamp": "1728897681",
  "accountNumber": "66925336",
  "shortcode": "415010"
}
```

A successful response includes the resolved account name:

```json
{
  "requestId": "dcd1c2ab-7a26-4170-939d-9dc2e879b0e5",
  "timestamp": 1793000000,
  "accountName": "Example Account",
  "accountNumber": "66925336",
  "shortcode": "415010"
}
```

The receiver returns `400` when the resolver finds no account, `401` for an invalid or expired token, and `422` for missing or malformed request fields. Use a shared Laravel cache store if your app runs on multiple instances so tokens issued by one instance can be validated by another.

C2B Hakikisha requires Safaricom onboarding and a partner agreement. Confirm the expected credentials, callback URLs, and account-resolution behavior with Safaricom before going live.
